# Directory Update Log

## 2026-11-04
* **Update**: [Player controls](player-controls.md), at the owner's request for the controls of other streaming apps: double tap on the left or right third seeks (−10/+30 s, further quick taps add up) with a bubble showing the seconds, big back/play/forward buttons over the video, mouse click plays/pauses and double click toggles fullscreen, and a Rotate to Landscape button that turns the player inside the app (`ephyra/rotator.py`; decision [rotate in the app](decisions/rotate-in-app.md), after reading Phosh's rotation and monitor managers). Checked under headless phoc at 360×720 and 1000×700; `tests/test_player.py` and the UI test cover the tap rules, the rotator's input mapping, seeking and rotating. Tests that play media now own the main context ([dev environment](dev-environment.md)); the full suite passed 15 runs in a row under headless phoc, before about every third run aborted. `Media.stop()` now releases gtk4paintablesink on the main thread; freed by the garbage collector on a proxy thread it aborted the app ([playback](playback.md)).
* **Update**: Nothing played on the phone: GTK 4.20's `Gtk.MediaFile` reads `http://` through GIO, which the Flatpak can't (found from the owner's `GST_DEBUG` log). New `ephyra/media.py` plays with `playbin3` and `gtk4paintablesink`; [playback](playback.md) and the decision [playbin instead of GtkMediaFile](decisions/playbin.md). Tested here: a clip through demo server and proxy (play, pause, seek, end, error; `tests/test_media.py`) and a Jellyfin-shaped HLS stream; the phone's runtime has `gtk4paintablesink`, `hlsdemux2` and the H.264/AAC/FLAC decoders.
* **Update**: [Playback](playback.md): the "Can't Play This" page shows one plain sentence and a selectable details line (container, codecs, the server's direct play / convert / converted stream answer, error code, the short GStreamer reason), so the owner can report a failing file from the phone without a terminal. The owner still saw only the error message on the phone while the browser played the file.
* **Update**: [Connection](connection.md): addresses without a scheme get `https://`, also the local one (owner's rule); the field shows the address as used. [Playback](playback.md): on the phone a file failed with "can't convert" because the server gives no `TranscodingUrl` when the user lacks *Allow video playback that requires transcoding* (`EnableVideoPlaybackTranscoding`, read in the server source); Ephyra now names that setting. "Convert on the Server" also disables stream copy, the token is stripped from the `TranscodingUrl`, and `EPHYRA_DEBUG=1` logs the server's decision.
